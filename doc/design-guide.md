# UIデザインガイド

- 作成日: 2026-10-08
- 対象: Quiz-Portfolio3 の全画面(v2 から引き継ぎ)
- 前提: [requirements.md](requirements.md) の「5. UI/UX 方針」(白黒基調のシックなデザイン / ライトモードのみ / スマホ・PC 両対応)

このガイドの値は Tailwind CSS v4 の `@theme`(`resources/css/app.css`)にデザイントークンとして定義する。画面側では **色コードや px 値を直接書かず、必ずトークンか共通コンポーネントを使う**。

## 1. 基本の考え方

1. **情報が主役**: 装飾で目を引かない。問題文・回答・点数が一番読みやすい状態にする
2. **白黒が基本、色は意味のあるところだけ**: 画面は白と黒(とグレー)で組む。黒は「操作できるもの・現在地」。色は「点数の良し悪し」と「状態」のバッジにだけ使う
3. **余白で区切る**: 罫線と影は最小限にする。まとまりは余白の大小で表す
4. **どの画面も同じ作法**: ボタンの位置、見出しの大きさ、一覧の形を全画面でそろえる

## 2. カラー

### 2.1 ニュートラル(Tailwind 標準の `neutral` を使う)

v3 は**黒と白を基調にしたシックなデザイン**にする(2026-10-11 決定)。青みのある `zinc` ではなく、色味のない `neutral` を使い、白黒をはっきりさせる。

| 用途 | トークン | 値 |
|---|---|---|
| ページ背景・カード・サイドバー背景 | `white` | #ffffff |
| ホバー背景・控えめな面 | `neutral-100` | #f5f5f5 |
| 罫線・カード枠 | `neutral-200` | #e5e5e5 |
| 入力欄の枠 | `neutral-300` | #d4d4d4 |
| 補足テキスト・プレースホルダ | `neutral-500` | #737373 |
| 本文テキスト | `neutral-700` | #404040 |
| 見出し・強調テキスト | `neutral-900` | #171717 |

### 2.2 アクセント(黒: `ink`)

アクセントカラーは使わず、**黒を「操作できるもの・現在地」の色**にする。v2 の青(`brand`)は使わない。

| トークン | 値 | 用途 |
|---|---|---|
| `ink` | #0a0a0a(`neutral-950`) | 主ボタンの背景、選択中のラジオの背景、フォーカスリング、リンクの文字 |
| `ink-hover` | #262626(`neutral-800`) | 主ボタンのホバー |

- 黒い面の上の文字は白にする
- リンクは黒文字 + 下線(色では見分けられないため、下線で操作できることを示す)

### 2.3 意味を持つ色

| 意味 | 背景 | 文字 | 使う場面 |
|---|---|---|---|
| 高得点(80〜100点) | `emerald-50` | `emerald-700` | 点数バッジ |
| 中得点(60〜79点) | `amber-50` | `amber-700` | 点数バッジ |
| 低得点(0〜59点 = 苦手) | `rose-50` | `rose-700` | 点数バッジ |
| 成功 | `emerald-50` | `emerald-700` | トースト、`completed` 状態 |
| 処理中 | `sky-50` | `sky-700` | `pending` / `grading` 状態 |
| エラー・危険 | `rose-50` | `rose-700` | エラー表示、削除ボタン、`failed` 状態 |

- 点数の区切り(60点)は、苦手判定の基準点(`config('quiz.weak_threshold')`)と同じ値を使う。80点の区切りは見た目だけのもの
- 色だけで意味を伝えない。点数バッジには数字、状態バッジには文字(`Grading` など)を必ず入れる

## 3. タイポグラフィ

### 3.1 フォント

```css
--font-sans: "Inter", "Noto Sans JP", system-ui, sans-serif;
```

- Inter: 400 / 500 / 600、Noto Sans JP: 400 / 500 / 700
- Laravel の Vite プラグインの `fonts`(`google()`)で、**ビルド時に Google Fonts から取り込み、自サイトから配信する**。表示のたびに外部へ取りに行かない(`vite.config.js`)
- Noto Sans JP は文字の範囲ごとに約120個のファイルに分かれている。ブラウザはページで使われている文字の範囲のファイルだけを取りに行くので、先読み(preload)はしない
- 英数字は Inter、日本語は Noto Sans JP で表示される
- v3 では画面の文言は英語だが、問題文・回答・採点コメントは日本語になるため、Noto Sans JP も引き続き読み込む(requirements.md 5.5)
- 点数などの数字には `tabular-nums` を付け、桁がそろうようにする

### 3.2 文字サイズ

| 役割 | クラス | サイズ / 太さ | 例 |
|---|---|---|---|
| 大きな数字 | `text-4xl font-semibold` | 36px / 600 | 結果画面の平均点 |
| ページ見出し | `text-2xl font-semibold tracking-tight` | 24px / 600 | `Categories` |
| セクション見出し | `text-lg font-semibold` | 18px / 600 | `Questions` |
| カード見出し | `text-base font-medium` | 16px / 500 | カテゴリ名 |
| 本文 | `text-body` | 15px / 行間 1.75 | 問題文、回答、フィードバック |
| UIテキスト | `text-sm` | 14px | ボタン、ナビゲーション、表 |
| 補足 | `text-xs text-neutral-500` | 12px | 日時、件数 |

- `text-body` は `@theme` で定義した独自のトークン(Tailwind 標準の sm と base の間のサイズ)
- 入力欄は **16px 以上**にする(iOS で入力時に画面が拡大されるのを防ぐため)
- 問題文・回答・フィードバックは改行を保持する(`whitespace-pre-wrap`)

## 4. 余白・サイズ・形

### 4.1 余白(4px 単位)

| 用途 | 値 |
|---|---|
| ページの左右余白 | スマホ 16px(`px-4`)/ PC 32px(`lg:px-8`) |
| ページ見出しと本文の間 | 24px(`mb-6`) |
| ブロック同士の間 | 32px(`space-y-8`) |
| カード同士の間 | 12px(`gap-3`) |
| カードの内側 | スマホ 16px / PC 20px(`p-4 lg:p-5`) |

### 4.2 本文の最大幅

| 画面の種類 | 最大幅 |
|---|---|
| フォーム(作成・編集) | 640px(`max-w-2xl`) |
| 一覧・詳細・回答・結果 | 768px(`max-w-3xl`) |

### 4.3 角丸と影

| 対象 | 角丸 | 影 |
|---|---|---|
| ボタン・入力欄 | 8px(`rounded-lg`) | なし |
| カード | 12px(`rounded-xl`) | `shadow-xs`(ごく薄く)+ `border-neutral-200` |
| モーダル | 16px(`rounded-2xl`) | `shadow-xl` |
| バッジ | 丸(`rounded-full`) | なし |
| トースト | 12px | `shadow-lg` |

### 4.4 押せる領域

- ボタン・リンク・リストの行は、高さ **44px 以上**(`min-h-11`)。PC では 40px(`lg:min-h-10`)まで下げてよい
- アイコンだけのボタンも 44 × 44px の領域を確保する

## 5. 動き

| 対象 | 時間 | 内容 |
|---|---|---|
| ホバー・フォーカス | 150ms | 背景色・枠線の色の変化(`transition-colors`) |
| モーダル・ドロワー | 200ms | フェード + わずかな拡大 / スライド |
| トースト | 200ms | 下からフェードイン。4秒後に自動で消える |
| 折りたたみ | 200ms | 高さの変化(Alpine の `x-collapse`) |

- `prefers-reduced-motion` が有効なら、トランジションを無効にする
- ローディング中のアニメーションはスケルトンの点滅(`animate-pulse`)だけにする。回転するスピナーは使わない

## 6. アイコン

- **Heroicons(Outline, 20px)** を使う。SVG を Blade コンポーネントに埋め込む(外部の CDN から読み込まない)
- 色は文字色に合わせる(`currentColor`)
- アイコンだけで意味を伝える場合は `aria-label` を付ける

## 7. 共通コンポーネント

Blade の匿名コンポーネントとして `resources/views/components/ui/` に置き、`<x-ui.button>` のように使う。

### 7.1 ボタン `<x-ui.button>`

| variant | 見た目 | 用途 |
|---|---|---|
| `primary` | `ink` 背景・白文字(ホバーで `ink-hover`) | 画面の主操作(1画面に原則1つ) |
| `secondary` | 白背景・`neutral-300` 枠・`neutral-700` 文字 | 副操作 |
| `ghost` | 背景なし・`neutral-600` 文字、ホバー時に `neutral-100` | ツールバー、控えめな操作 |
| `danger` | `rose-600` 背景・白文字 | 確認モーダル内の削除実行のみ |

- サイズは `md`(既定: 高さ 44px / PC 40px)と `sm`(高さ 32px。表の中など)
- `href` を渡すと `<a>`、渡さないと `<button>` として出力する
- 処理中は `disabled` + 文言の切り替え(例: `Submit (8)` → `Submitting…`)

### 7.2 入力欄 `<x-ui.input>` / `<x-ui.textarea>`

- ラベルは入力欄の上に置く(プレースホルダだけで済ませない)
- フォーカス時: `border-ink` + `ring-1 ring-ink`
- エラー時: `border-rose-500`、入力欄の直下に `text-sm text-rose-600` でメッセージを表示する
- 文字数の目安がある項目は、右下に「120 / 2000」のように文字数を表示する

### 7.3 カード `<x-ui.card>`

- 白背景・`border-neutral-200`・`rounded-xl`・`shadow-xs`
- リンクになるカード(一覧の1件など)は、ホバー時に枠を `neutral-400` にする(背景は白のまま)

### 7.4 バッジ `<x-ui.score-badge>` / `<x-ui.status-badge>`

- 点数バッジ: 2.3 の色分けで点数を表示する。点数がまだない場合は `neutral-100` 背景で「—」
- 前回比: 点数バッジの右に小さく `▲16`(`emerald-600`)/ `▼8`(`rose-600`)/ `±0`(`neutral-500`)。初回は `New`
- 状態バッジ: `pending` `Waiting` / `grading` `Grading` / `completed` `Done` / `failed` `Failed`(screens.md 4.4)
- 種別バッジ: `all` `All` / `weak` `Weak`(`neutral-100` 背景の控えめな表示)

### 7.5 トースト `<x-ui.toast>`

- 画面の右下(スマホでは下中央)に表示する
- 成功(緑のチェックアイコン)/ エラー(赤のアイコン)の2種類
- 4秒で自動的に消える。×ボタンで手動でも閉じられる
- コントローラからは `->with('toast', ['type' => 'success', 'message' => '...'])` で渡す
- `role="status"`(エラーは `role="alert"`)を付ける

### 7.6 確認モーダル `<x-ui.confirm-modal>`

- 背景: `neutral-900/40` の半透明
- 中身: タイトル、説明文(一緒に消えるデータの件数)、`Cancel`(secondary)、`Delete`(danger)
- Esc キーと背景クリックで閉じる。開いたら `Cancel` にフォーカスを移す(誤操作防止)
- 削除はフォームの `DELETE` 送信。モーダルは Alpine で開閉する

### 7.7 パンくず `<x-ui.breadcrumb>`

- `Categories › 〇〇 › △△` の形。最後の項目(現在地)はリンクにせず `neutral-900`
- スマホで長い場合は、途中を省略し「… › △△」にする

### 7.8 空の状態 `<x-ui.empty-state>`

- 枠線を点線(`border-dashed`)にしたカードの中に、アイコン・一文の説明・主ボタンを中央寄せで置く
- 例: `No questions yet.` + `Add question`

### 7.9 スケルトン `<x-ui.skeleton>`

- `neutral-100` の角丸ブロック + `animate-pulse`
- 採点待ち画面で、結果カードの形をあらかじめ表示しておくために使う

### 7.10 メニュー `<x-ui.dropdown>`

- 「…」ボタンを押すと、編集・削除などの副操作を表示する
- 一覧の各行や詳細画面の右上に置き、画面を操作ボタンで埋めないようにする

### 7.11 切り替えボタン `<x-ui.radio-group>`

- 少ない選択肢(2〜4個)から1つを選ぶ入力に使う(採点レベルなど)。横幅を等分して横並びにする
- 中身は普通のラジオボタン(画面には出さない)なので、キーボードの矢印キーでも選べる
- 選ばれている項目は `ink` 背景・白文字にする(白黒の切り替えスイッチの見た目)

## 8. アクセシビリティ

- 文字と背景のコントラストは WCAG AA(本文 4.5:1 以上)を満たす
- キーボードで全操作ができること。フォーカスは常に見えるようにする(`focus-visible:ring-2 ring-ink ring-offset-2`)
- フォームのラベルと入力欄は `for` / `id` で関連付ける
- モーダル表示中はフォーカスをモーダル内に閉じ込める(Alpine の `x-trap`)
- 画面ごとに `<title>` を「ページ名 | recollect」の形で付ける(例: `Categories | recollect`)
- `<html lang="en">` にする。日本語が入る問題文・回答・採点コメントの要素には `lang="ja"` を付ける(読み上げソフトが正しい言語で読むように)
