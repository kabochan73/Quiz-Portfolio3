- 前提: [requirements.md](requirements.md)、[design-guide.md](design-guide.md)、[screens.md](screens.md)、[architecture.md](architecture.md)

## 1. 進め方

### 1.1 横切り開発(2026-10-11 決定)

v3 は**横切り(レイヤーごと)**で作る。v2 は機能ごとに「画面・処理・テスト」をまとめて作る縦切りだったが、v3 では全機能の同じ層をまとめて作り、下の層から順に積み上げる。

```
フェーズ1 土台(プロジェクト・Docker・CI・設定)
フェーズ2 データ層   … 全テーブル・Enum・モデル・Factory・Seeder
フェーズ3 ロジック層 … 採点サービス・集計クエリ・履歴の整理・採点 Job
フェーズ4 HTTP 層    … ルート・FormRequest・コントローラ
フェーズ5 画面層     … 共通UI(デザイントークン・共通コンポーネント・エラーページ)→ 全画面の Blade・ブラウザ側の JS
フェーズ6 仕上げとデプロイ
```

- 各層は、その下の層だけに依存する。上の層(画面など)がなくても、その層のテストが通る状態でフェーズを終える
- フェーズ4 の時点では画面がないため、ブラウザで通しの操作ができるのはフェーズ5 から。それまではテストで動作を確かめる
- **共通UIは画面層の最初に作る**(2026-10-12 変更)。v2 は縦切りで最初の機能から画面が必要だったため共通UIを2番目のフェーズにしていたが、横切りでは画面を作るのはフェーズ5からなので、使う直前に作る
- UI/UX が柱なのは v2 と同じ。**共通コンポーネント(5-1〜5-6)を先に作り、各画面(5-7 以降)はそれを組み合わせて作る**。画面ごとに独自のスタイルを書かない

### 1.2 コミット

- コミットの粒度は v2 を踏襲し、**1コミット = 5ファイル前後**(テストを含めて、目安 3〜8 ファイル)にする
  - 例外: Laravel プロジェクトの生成、パッケージ導入時の lock ファイルなど、自動で生成されるファイルが多いもの
- 1コミット = その層の中の1つのまとまり(例: 「categories/sections/questions のマイグレーションを追加」)
- コードとそのテストは同じコミットに含める
- コミットメッセージは日本語で「何をしたか」を1行で書く(v1・v2 と同じ)
- コミット前に Pint とテストを通す

## 3. テストの方針

### 3.1 Unit テスト(`tests/Unit`)

DB や API に依存しない、純粋なロジックを対象にする。

| 対象 | 確認すること |
|---|---|
| `GradeResultParser` | 正常な結果、件数の不一致、position の重複・抜け、空文字、点数の範囲外 |
| プロンプトの組み立て | タグで囲まれること、`<` `>` のエスケープ、採点レベルごとの文言、フィードバックの書き方の指示が入っていること |
| `CostCalculator` | 計算結果、単価が未設定のモデル |
| Enum | ラベル、採点方針の文言 |

### 3.2 Feature テスト(`tests/Feature`)

| 対象 | 確認すること |
|---|---|
| 認証 | ログイン / ログアウト、未ログインでのアクセス拒否、試行回数の制限 |
| カテゴリ / セクション / 問題 | 作成・更新・削除、バリデーション、cascade 削除、10問の上限 |
| 回答の送信 | Attempt と Answer の保存、Job の投入、リダイレクト、他セクションの問題の混入を拒否、weak モードの対象チェック |
| `GradeAttempt` Job | 成功時に scores と使用量が保存されること、失敗時に failed になること、完了済みの挑戦は処理しないこと |
| 結果画面 | 状態ごとの表示、状態確認 API、再採点 |
| 集計 | 最新の点数、前回の点数、苦手問題の抽出(未採点・失敗の挑戦を除くこと) |
| 履歴の整理 | 11件目以降の削除、空になった挑戦の削除(古い回答の整理と問題の削除の両方) |
| URL の親子関係 | 別のセクションの挑戦を指定すると 404 が返ること、未ログインではログイン画面へ移ること |

- Claude API は、テストでは `FakeGradingService` に差し替える
- `ClaudeGradingService` の2段階の呼び出しは、API クライアントをモックして確認する
